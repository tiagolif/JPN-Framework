# Biblioteca de Exemplos JPN

Esta pasta demonstra como aplicar **Jornada, Precisão e Narrativa** em domínios diferentes. Os exemplos são referências de estrutura e raciocínio operacional; não prometem resultado e não substituem validação específica do ambiente.

## Exemplos disponíveis

| Exemplo | Foco principal |
|---|---|
| `software-development.md` | requisitos, critérios de aceite e testes de software |
| `document-analysis.md` | evidência, rastreabilidade, lacunas e conflito documental |
| `sales-agent.md` | qualificação comercial com guardrails de preço/estoque/oferta |
| `customer-support.md` | atendimento comercial, CRM, fallback e handoff |
| `technical-support.md` | diagnóstico progressivo e escalonamento seguro |

| `multiagent-handoff.md` | contratos de handoff e estado explícito entre agentes |
| `rag-conflicting-sources.md` | governança e tratamento de fontes conflitantes em RAG |
| `crm-state.json` | exemplo estruturado de estado aplicado a CRM |
| `jpn-state.example.json` | exemplo genérico de estado JPN estruturado |

## Como usar

1. Escolha o exemplo mais próximo do seu problema.
2. Reescreva a **Jornada** com o contexto, objetivo, recursos, restrições e incertezas reais.
3. Converta a **Precisão** em critérios que possam ser verificados.
4. Use a **Narrativa** para ordenar execução, validação e próxima ação.
5. Preserve lacunas explícitas em vez de inventar dados ausentes.
6. Antes de automatizar ações de alto impacto, defina autoridade, fallback e revisão humana.

## Regra de adaptação

Não copie detalhes de domínio como se fossem universais. O que deve permanecer é a disciplina: contexto explícito, critérios verificáveis, origem de evidência, limites declarados e sequência de execução clara.
